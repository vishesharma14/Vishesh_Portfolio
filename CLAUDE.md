# Vishesh Sharma — Personal Portfolio

Project rules for Claude Code sessions in this repo. This file is self-contained: read all of it before changing anything.

## Workflow (mandatory)

- Work on **one roadmap step per request**. Never build ahead or start the next step unprompted.
- For every step: inspect the existing code first → implement only that step → `npm run format` → `npm run check` → `npm run build` → verify UI changes in a real browser at 390, 768 and 1280px → report files changed, checks and test results → **stop and wait** for approval.
- After every step, make sure the dev server is running (start `npm run dev` in the background only if nothing is listening on port 5173), and end the report with clickable local links to every section or page the step added or changed.
- Fix real failures before stopping; don't make extra improvements after verification.
- Never delete or rewrite working code unnecessarily. Add a dependency only in the step that needs it.
- **Git:** never commit, push or deploy unless explicitly asked. After a step is approved the user may ask for a milestone commit: stage only that step's files (never `.env*` other than `.env.example`, never secrets), push to `origin/main`, never force-push, then confirm local `main`, `origin/main` and GitHub `main` match and the tree is clean. Every push to `main` deploys the live site (Vercel project `vishesh-sharma`, https://vishesh-sharma.vercel.app).
- Run commands from the repo root. The shell is Git Bash on Windows.

## Content rules

- No fake personal information, no generated or stock profile photos, and no fake functionality presented as real (e.g. a contact form that doesn't send).
- When real content is missing, use a clearly temporary placeholder that cannot pass as real data.
- **No certifications anywhere:** no section, no database table, nothing in chatbot knowledge (the bot says it has no information about that).
- **No internship or work-experience entry anywhere:** no section, no table, nothing in chatbot knowledge.
- Portfolio content is never hardcoded in components (see Architecture).
- Secrets only in environment variables: never in source, in this file or in `VITE_*` variables.

## Design system (approved; preserve it)

- Off-white canvas, deep navy text, white cards, subtle borders and shadows, generous spacing, Inter Variable (self-hosted), restrained motion. The exceptions are two full-width dark bands, the Hero at the top and the Contact band at the end, so the page starts and ends on the same note; every section between them stays on the light canvas.
- **One accent only:** deep indigo / blue-violet. Avoid rainbow colours, neon, glow, large gradients, 3D, glassmorphism, excessive animation and clutter.
- **One glow only:** `bg-accent-glow`, the soft indigo light behind the Hero portrait (radial, at most 25% opacity, no animation of its own). Nowhere else, so nothing on night gets a coloured shadow (the primary button and the navbar monogram drop theirs there).
- **Dark Hero band:** `night-950` (≈ #0B1020, the band), `night-900` (raised surfaces: study card, mobile menu panel) and `night-800` (hairlines), plus `success-400` for the availability dot. The band's bottom edge is straight. On night, text is white (name, fact values), light accent (`accent-200` role line, `accent-400` separators) or light ink (`ink-200` chip, `ink-300` intro, `ink-400` labels, muted links and the scroll cue): all at least 4.5:1, even over a dot of the white 7% dot grid. Buttons use `buttonStyles({ tone: 'dark' })`: primary `accent-500` with white text (5.2:1, `accent-600` on hover); secondary outlined (`border-white/20`, white text, `hover:bg-white/10`). Put `on-dark` on dark surfaces: their focus rings switch to `accent-300` (9.3:1 on night).
- **Dark Contact band:** `#contact`, the last section before the footer, matches the Hero: `night-950`, the white dot grid on its own layer, no glow, straight edges. It is as tall as its content and padding (`py-section`), but at least the largest screen height minus the navbar and 12rem (less than the footer is ever tall), so it can always scroll up under the navbar; that floor only matters on tall screens (tablets held upright, 1080p desktops), with the content centred within it. If the footer ever gets shorter than 12rem, lower that allowance. Title white, description `ink-300`, actions with `buttonStyles({ tone: 'dark' })` at 44px: Email (primary), Copy email, the phone when shown, then the profile links (LinkedIn first). Email ("Email Vishesh", `EmailAction`) is a mailto: link on touch devices (`(pointer: coarse)`) and in any HTML rendered before JavaScript runs; elsewhere it opens Gmail's compose window in a new tab. Below the buttons, the address is shown as plain text that can be selected (`EmailAddress`), followed on desktop by "Use another email app" (mailto:). Both links fill in `contact.emailSubject`, and the URLs are built from the content (`emailLinks.ts`). On phones, one full-width button per row. No form until Step 18.
- **Navbar:** dark (`night-950`, white text, the current section as a white label on an indigo pill) while a dark band (the Hero or the Contact band) is under it, the light navbar everywhere else, including project pages and the 404 page from the start. Each band calls `useDarkBandUnderNavbar(ref)`: a band counts while it covers the navbar's bottom edge (its top may sit up to 1px lower, so a band a section link lands on counts), two IntersectionObservers report its bottom and top edges crossing that edge, and the hook sets `data-navbar-tone="dark"` on `<html>` while any band counts. Navbar elements style their dark look with the `navbar-dark:` variant (globals.css), which applies only inside `[data-navbar]`. Only colours change: a 200ms fade, instant with reduced motion, and a page's first colour never fades in (`data-navbar-instant`).
- Tokens live in `src/styles/globals.css` (`@theme`). Tailwind's default palette is removed (`--color-*: initial`), so use `canvas`, `surface`, `ink-*`, `accent-*`, `night-*`, `danger-*`, `success-*` and the semantic `fg`, `fg-muted`, `fg-subtle`, `border`, `border-strong`, `border-input`.
- Other tokens: text `display|title|heading|lead|eyebrow` (`display` is the Hero name, sized to its `@container` in `cqi`); spacing `section`, `gutter`, `header`; containers `content`, `narrow`; shadows `card`, `card-hover`, `accent`; easing `smooth`. Utilities in `globals.css`: `bg-accent-wash`, `text-accent-gradient`, `bg-dot-grid` (white dots for the dark bands, on their own decorative layer), `bg-accent-glow` (the one glow, see above), `on-dark` (focus rings for dark surfaces), `animate-rise` (entrance fade-and-rise; only as `motion-safe:animate-rise`, staggered with `[--rise-delay:…]`) and `animate-nudge` (three gentle beats for a scroll cue; only with `motion-safe:`). Register any new custom token in `src/lib/cn.ts` (tailwind-merge) too. Colours need no entry there (any colour name counts as a colour), but `bg-*` background-image utilities do, under `bg-image`.
- Accessibility: WCAG AA contrast (text ≥ 4.5:1, form-field outlines ≥ 3:1), visible focus ring, skip link, semantic landmarks, touch targets ≥ 44px, `prefers-reduced-motion` honoured (CSS safety net in `globals.css`; use `motion-safe:` for movement).
- Buttons keep a visible text label at every width, phones included: no icon-only buttons (the navbar's menu toggle, named "Menu" for screen readers, predates this rule).
- Base UI in `src/components/ui/`: `Button`/`ButtonLink` (`buttonStyles()` styles router links), `Card`, `Badge`, `Container`, `Section`, `SectionHeader`, form controls, `SkipLink`, and `cardGrid.ts` (the 1/2/3-column card grid of Skills and AI / GenAI; `cardSpan()` keeps the last row full: a last card alone spans the row, and a last row of two shares the 3-column row equally).

## Architecture

- Folders: `src/app/` (router, root layout, navigation config, site identity), `src/components/ui/` and `src/components/layout/`, `src/features/<section>/` (one folder per page section, e.g. `hero/`, plus `chatbot/`), `src/pages/` (route pages that compose the features), `src/admin/` (lazy-loaded chunk), `src/hooks/`, `src/lib/`, and `src/content/`.
- **Content:** components read content only through hooks (`useProfile()`, `useProjects()`, …) imported from `src/content/index.ts`, never from `local/` directly. Schemas in `src/content/schema.ts` are the single source of truth (types are inferred from them) and only validate, never change values. Real local content lives in `src/content/local/`, with `TODO(content)` notes where details aren't verified yet. All hooks go through one `useContent()`, which is the only thing that changes when the source switches to Supabase (Step 13). The app imports content types only, so zod stays out of the browser bundle.
- **Page metadata:** `src/app/site.ts` (site identity) holds the home page's title and description, `themeColor` (night-950), the social image and `url` (the live origin, `https://vishesh-sharma.vercel.app`; every absolute URL is built from it). `vite.config.ts` writes them into the `<head>` of `index.html` (title, description, theme-color, Open Graph and Twitter tags, `og:url` and `og:image` absolute) plus the preload of the Latin Inter file, looked up by name in the bundle (the build fails if it's missing). Its `sitemap()` plugin writes `sitemap.xml` into the build (no file in `public/`): the home page and each featured project's page, from the local content, so it can't drift from the site. `public/robots.txt` names the sitemap's URL: change it with `url`. Crawlers that don't run JavaScript, including every link preview, see the home page's tags on every URL. Each page renders `PageMetadata` (title, description, canonical on `url`, or `noindex` instead on the 404 page): project pages "<title> · Vishesh Sharma" with the project summary. `main.tsx` removes the static title and description first, because React adds its own next to them rather than replacing them.
- **Navigation:** the navbar, the mobile menu and the footer list only the sections the home page renders (`useSectionNav()` in `src/app/useSectionNav.ts`), so no link leads nowhere; on other pages the same links point back to `/#id`. `useRenderedSections()` there repeats each section's rule for rendering nothing, so change both together. HomePage also uses it to pass `showContact` to `<Hero>`.
- **Supabase:** Postgres, Auth and Storage. Row-level security is the security layer: `is_admin()` requires an `admins` allowlist entry **and** an MFA-verified session. The public can read only published or visible rows. Sign-ups are disabled. SQL lives in `supabase/migrations/`.
- **Browser env vars:** only `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`. Everything else is server-only (names in `.env.example`).
- **Server:** Vercel functions in `api/` (`chat`, `contact`, `github`), server-only helpers in `server/`, shared schemas in `shared/`. Never import `server/` from `src/`.
- **Chatbot:** `/api/chat` builds the knowledge text from published content, uses a cached system prompt (no RAG), streams replies, validates input and rate-limits. The model comes from the `CHAT_MODEL` env var; never hardcode one.
- **Chatbot switch:** `CHATBOT_ENABLED` in `src/features/chatbot/config.ts` stays `false` until Step 21. The Hero's chatbot entry renders only when the switch is on **and** a real `onOpenChat` handler is passed to `<Hero>`, so nothing can look clickable without working. While off, the production build drops the entry's code.
- **Admin:** `/admin/*` is lazy-loaded; email + password + TOTP MFA. Route guards only control what the UI shows.

## Gotchas

- Section links are `Link to="/#id"`. React Router's `ScrollRestoration` scrolls to them using CSS smooth scrolling (`scroll-padding-top` is the navbar height), or to the top when the section doesn't exist yet. No custom scroll JavaScript.
- `ScrollRestoration` has a `getKey` that keys fresh page loads by URL, because React Router gives every fresh load the same key, `"default"`.
- Page changes (a new pathname, including browser Back) must jump, not glide: `InstantScrollOnPageChange` in `RootLayout` turns CSS smooth scrolling off for the one scroll React Router makes, so it must stay rendered just before `ScrollRestoration`. Section links on the same page still scroll smoothly.
- IntersectionObserver reports only after the first paint. So `useDarkBandUnderNavbar` measures the navbar's starting colour once, in a `requestAnimationFrame` (after React Router's scroll restoration, which runs in a layout effect, and before the first paint), and shows it without a fade. Without that, the navbar would flash or fade on every home load and on Back.
- The navbar's tone is a DOM attribute, not React state: `useSyncExternalStore` subscribes in a passive effect, after the first paint, so a store-based navbar showed one light frame on every fresh home load.
- Chrome puts CSS `uppercase` into accessible names. A visible uppercase label that names a list ("Tech stack", "Used in") is `aria-hidden`, and the list gets the same words as its `aria-label`.
- The skip link appears over both the dark and the light navbar, so its focus ring is drawn just inside its own white pill (`-outline-offset-2`).
- The root route needs `HydrateFallback`; React Router 8 warns on direct loads of lazy routes without it.
- The mobile menu closes on navigation by remembering the `location.key` it was opened at (the React Hooks lint rules forbid setState inside effects).
- Tailwind 4 animates the `translate` and `scale` properties, not `transform`, so name those in `transition-[...]`.
- `vercel.json`: every path that isn't a real file is rewritten to `/index.html` (deep links such as `/projects/sizerai` and `/admin`; the app shows its 404 page), except under `/assets/`, where a missing hashed file stays a real 404 rather than HTML under the one-year cache. Vercel serves real files before rewrites (`@vercel/routing-utils` puts `handle: filesystem` ahead of them). Every response gets `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY` and a `Permissions-Policy` turning off camera, microphone and geolocation; `/assets/*` (content-hashed) gets `Cache-Control: public, max-age=31536000, immutable`, everything else Vercel's default (`max-age=0, must-revalidate`). Two header rules must never set the same key: Vercel doesn't document which one wins. None of this applies to `npm run dev` or `npm run preview`.
- `X-Frame-Options: DENY` also stops the Résumé section framing its own PDF in production. If a résumé is added while the preview is still that frame, give PDFs `SAMEORIGIN` first (or `frame-ancestors 'self'` in the Step 22 CSP); Step 17's image preview removes the frame.
- With motion allowed, a fresh load of `/#section` glides there from the top (CSS smooth scrolling), so on `/#contact` the navbar goes dark, light, dark. Check a page's first navbar colour with reduced motion.
- Copy email renders only in a secure context (https, localhost). Opened over the LAN (`http://192.168…`, e.g. from a phone) it isn't there.
- Code that reads browser APIs while rendering (pointer type, clipboard) goes through `useSyncExternalStore` with a server snapshot (`useCoarsePointer`, `CopyEmailButton`), so the Contact section also renders without a browser: the Email button is then the mailto: link. Headless Chrome reports a fine pointer; emulate phones with `Emulation.setTouchEmulationEnabled` so `(pointer: coarse)` matches.
- Chrome's PDF viewer draws a dark margin (about 10px) around the page, so the résumé preview's iframe is 1rem larger than its frame on every side and the frame crops it. Browsers that can't show PDFs inline (`navigator.pdfViewerEnabled` false, e.g. Chrome on Android) get no preview. Step 17 replaces the frame with an image of page 1.
- Headless Chrome ignores `--window-size` below about 500px; emulate viewports through the DevTools protocol instead.
- Verifying hidden states (resume, chatbot, photo) happens in a scratchpad copy, never in the repo. Those scripts must use `set -euo pipefail`, check that the copy path is inside the scratchpad, and use absolute paths for every edit. Never rely on `cd` inside an `&&` chain: if an earlier command fails, later lines run in the real repo. Create the `node_modules` junction with PowerShell `New-Item -ItemType Junction`, and remove the junction itself (`(Get-Item path).Delete()`) before deleting the copy, or `rm -rf` can follow it into the real `node_modules`.
